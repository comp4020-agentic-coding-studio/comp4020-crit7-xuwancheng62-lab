# Crit 7

## What was the breakthrough that moved the work forward?

Asking "what does the student actually know?" instead of "what's wrong with
this screen?". My first notes were visual: semesters out of order. The real
problem was the interaction model. ISIS works, but it asks for a Class Number,
an internal identifier that means nothing to a student. Once I saw that the
Class Number belongs to the system, not the student, the rest followed.

I nearly repeated the mistake with COMP4020 and COMP8020. My first idea was to
list both and let the student pick, until I realised the system already knows
their study level and should resolve it. The same question showed that search
wasn't enough: search assumes you already know what you want, so I added a
catalogue for browsing.

## What did this work change about who I want to be as a software developer?

The quality of what the agent built depended on my pushback. Claude Code's
plans were technically sound, but some drifted from the goal, like letting
students add straight from a search result, or growing the scope. I kept
understanding the course as a required step, and kept real ANU authentication
and a degree-rules engine out.

I want to be the developer who owns the problem. The agent speeds up the
implementation; I stay responsible for what the user needs, where the
boundaries are, and whether each change still serves them. The result isn't a
reskin of ISIS: the student says what they want to study, and the system
handles the administration.
